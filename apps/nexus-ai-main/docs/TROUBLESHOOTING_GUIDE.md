## المشاكل الرئيسية

### 1. استيرادات خاطئة مع إصدارات محددة

#### ❌ الوصف
```typescript
// خاطئ
import { Slot } from "@radix-ui/react-slot@1.1.2";

// صحيح
import { Slot } from "@radix-ui/react-slot";
```

#### 🔍 السبب
- نسخ مكونات من shadcn/ui أو مكتبات أخرى تحتوي على إصدارات محددة
- عدم تنظيف الاستيرادات بعد النسخ
- استخدام أدوات توليد تضيف إصدارات تلقائيًا

#### 💥 التأثير
- أخطاء "Failed to resolve import" أثناء التشغيل
- فشل في تحليل التبعيات
- توقف التطبيق عن العمل

#### ✅ الحل المطبق
```bash
# إصلاح جميع الاستيرادات في ملفات UI
Get-ChildItem -Path "components/ui" -Filter "*.tsx" -Recurse | ForEach-Object {
    $content = Get-Content $_.FullName -Raw
    $content = $content -replace '@radix-ui/[^@]+@\d+\.\d+\.\d+', '$&' -replace '@\d+\.\d+\.\d+', ''
    $content = $content -replace 'class-variance-authority@\d+\.\d+\.\d+', 'class-variance-authority'
    $content = $content -replace 'lucide-react@\d+\.\d+\.\d+', 'lucide-react'
    Set-Content $_.FullName $content
}
```

#### 🛡️ الوقاية
- **فحص تلقائي**: أضف سكريبت في `package.json`:
```json
{
  "scripts": {
    "lint-imports": "grep -r '@.*@\\d' src/ && echo '❌ Found versioned imports!' || echo '✅ All imports clean'"
  }
}
```

- **قاعدة ESLint**: أضف قاعدة للكشف عن الاستيرادات المُحددة
- **مراجعة قبل الإضافة**: تحقق من الاستيرادات عند نسخ مكونات جديدة
- **أدوات تنظيف**: استخدم أدوات مثل `organize-imports` في VS Code

### 2. تضارب في إصدارات التبعيات

#### ❌ الوصف
```json
// package.json
"@radix-ui/react-slot": "^1.2.3"

// لكن الكود يتوقع
"@radix-ui/react-slot": "^1.1.2"
```

#### 🔍 السبب
- تحديث `package.json` دون التحقق من توافق المكونات
- استخدام مكونات من إصدارات مختلفة
- عدم تشغيل `npm install` بعد التغييرات
- مشاركة تبعيات بين تطبيقات في monorepo

#### 💥 التأثير
- أخطاء "Cannot find module"
- فشل في البناء
- سلوك غير متوقع في المكونات

#### ✅ الحل المطبق
1. تحديث `package.json` ليطابق إصدارات المكونات
2. تشغيل `npm install` لإعادة التثبيت
3. التحقق من توافق الإصدارات

#### 🛡️ الوقاية
- **فحص التوافق**: استخدم `npm ls` للتحقق من الإصدارات المثبتة
- **تحديث متزامن**: دائمًا شغل `npm install` بعد تغيير `package.json`
- **اختبار بعد التحديث**: شغل التطبيق واختبر المكونات
- **تجميد الإصدارات**: استخدم `package-lock.json` لضمان الاستقرار
- **فحص التبعيات**: أضف سكريبت:
```json
{
  "scripts": {
    "check-deps": "npm ls --depth=0"
  }
}
```

### 3. مسح Vite للملفات في التطبيقات الأخرى

#### ❌ الوصف
```
Error: The following dependencies are imported but could not be resolved:
  @google/generative-ai (imported by C:/nexus/apps/web-chatbot/nexus/index.tsx)
```

#### 🔍 السبب
- Vite يمسح المشروع بأكمله في monorepo
- عدم فصل التطبيقات بشكل صحيح
- تبعيات من تطبيقات أخرى تظهر في التطبيق الحالي

#### 💥 التأثير
- أخطاء في تبعيات غير مستخدمة
- بطء في البناء
- تضارب في التبعيات

#### ✅ الحل المطبق
```typescript
// vite.config.ts
export default defineConfig({
  root: __dirname, // حدد الجذر للتطبيق الحالي
  optimizeDeps: {
    exclude: [
      '@google/generative-ai', // استبعد تبعيات التطبيقات الأخرى
    ],
  },
});
```

#### 🛡️ الوقاية
- **تكوين منفصل**: كل تطبيق له `vite.config.ts` خاص
- **استبعاد التبعيات**: حدد `exclude` في `optimizeDeps`
- **تشغيل منفصل**: شغل كل تطبيق من مجلده الخاص
- **فصل التبعيات**: لا تشارك تبعيات بين التطبيقات إلا عند الضرورة

### 4. عدم تطابق إصدارات التبعيات

#### ❌ الوصف
```json
// package.json
"lucide-react": "^0.544.0"

// لكن المكونات تتوقع
"lucide-react": "^0.487.0"
```

#### 🔍 السبب
- تحديث تلقائي للتبعيات دون اختبار
- نسخ مكونات من مشاريع أخرى
- عدم التحقق من التوافق

#### 💥 التأثير
- أخطاء في وقت التشغيل
- مكونات لا تعمل بشكل صحيح
- مشاكل في التصميم

#### ✅ الحل المطبق
- تحديث `package.json` ليطابق الإصدارات المطلوبة
- إعادة تثبيت التبعيات
- اختبار جميع المكونات

#### 🛡️ الوقاية
- **اختبار شامل**: اختبر جميع المكونات بعد تحديث التبعيات
- **نسخ احتياطي**: احتفظ بنسخة من `package.json` قبل التغييرات الكبيرة
- **تحديث تدريجي**: حدث تبعية واحدة في كل مرة
- **فحص التوافق**: تحقق من documentation المكتبة

### 5. مشاكل CSS و Tailwind

#### ❌ الوصف
الموقع يظهر كـ HTML بسيط بدون ألوان أو تنسيق

#### 🔍 السبب
Tailwind CSS v4 يتطلب إعداد مختلف عن v3:
- استخدام `@tailwindcss/postcss` بدلاً من `tailwindcss`
- استخدام `@import "tailwindcss";` بدلاً من `@tailwind base;`

#### 💥 التأثير
- موقع بدون ألوان أو تنسيق
- يبدو مثل صفحات HTML من التسعينات
- Dark/Light mode لا يعمل

#### ✅ الحل المطبق
1. **إنشاء `postcss.config.js`**:
```js
export default {
  plugins: {
    '@tailwindcss/postcss': {},
  },
};
```

2. **تحديث `package.json`**:
```json
"devDependencies": {
  "@tailwindcss/postcss": "^4.1.14"
}
```

3. **تحديث `globals.css`**:
```css
@import "tailwindcss";
```

#### 🛡️ الوقاية
- **معرفة الإصدار**: تأكد من فهم متطلبات الإصدار المستخدم
- **قراءة التغييرات**: اقرأ release notes عند التحديث
- **اختبار فوري**: اختبر CSS فور التحديث
- **توثيق الإعداد**: احتفظ بملاحظات عن إعداد CSS

## الحلول والوقاية

### 🛠️ أدوات وقائية

#### 1. سكريبتات في package.json
```json
{
  "scripts": {
    "lint-imports": "grep -r '@.*@\\d' src/",
    "check-deps": "npm ls --depth=0",
    "validate": "npm run lint-imports && npm run check-deps && npm run type-check",
    "clean-install": "rm -rf node_modules package-lock.json && npm install"
  }
}
```

#### 2. ESLint قواعد مخصصة
```json
{
  "rules": {
    "no-restricted-imports": [
      "error",
      {
        "patterns": ["@*/**@\\d+\\.\\d+\\.\\d+"]
      }
    ]
  }
}
```

#### 3. Pre-commit hooks
```bash
# استخدم husky للتحقق قبل الcommit
npm install --save-dev husky
npx husky init
```

### 📋 قائمة تحقق قبل الإضافة

#### عند إضافة مكون جديد:
- [ ] تحقق من الاستيرادات (لا إصدارات محددة)
- [ ] تأكد من توافق التبعيات
- [ ] اختبر المكون في جميع السمات
- [ ] تحقق من الاستجابة

#### عند تحديث تبعية:
- [ ] اقرأ release notes
- [ ] اختبر جميع المكونات المعتمدة عليها
- [ ] شغل `npm ls` للتحقق من التوافق
- [ ] احتفظ بنسخة احتياطية

#### عند العمل في monorepo:
- [ ] شغل كل تطبيق من مجلده الخاص
- [ ] استبعد تبعيات التطبيقات الأخرى
- [ ] استخدم `root: __dirname` في vite.config.ts
